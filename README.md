# Portly

极简的 macOS 菜单栏 SSH 隧道应用。管理两个固定 SSH 主机，采用紧凑窗口、状态卡片与独立开关的界面，提供菜单栏快捷操作和本地端口设置；无插件或第三方依赖。

| 连接 | SSH 别名 | 本地端口 | 远端地址 |
| --- | --- | --- | --- |
| AWS Proxy | `aws-proxy` | `127.0.0.1:17890` | `127.0.0.1:17890` |
| Local Proxy | `local-proxy` | `127.0.0.1:17891` | `127.0.0.1:17891` |

## 构建并运行

需要 macOS 12+ 和完整的 Xcode。

1. 双击 `Portly.xcodeproj`，或运行 `open Portly.xcodeproj`。
2. 顶部 Scheme 选择 **Portly**，运行设备选择 **My Mac**。
3. 按 **⌘R** 构建并运行；按 **⌘B** 仅构建。

工程会自动构建并嵌入 SSH 认证辅助程序，使用本机临时签名，无需选择开发团队。运行前请先退出已打开的旧版 Portly，避免同时运行多个实例。

命令行构建也使用同一个 Xcode 工程，生成 Release 应用：

```sh
bash build.sh
open build/Portly.app
```

也可以在 Finder 双击 `build/Portly.app`，或拖入 Applications。启动时打开主窗口，顶部「概览」查看两个隧道及故障详情，「设置」修改本地端口。没有 Dock 图标，关闭窗口后可从顶部菜单栏的「打开 Portly…」重新打开。

点击连接项连接，再点一次停止；连接中点击取消。启动时默认断开，正常退出时关闭这两个隧道，包括已识别并核对目标的现有 SSH 连接。关闭窗口仍保留在菜单栏运行；点击「退出 Portly」才会关闭连接。

- 灰色：已手动停止或尚未连接。
- 橙色：正在连接，或检测到 SSH 监听但尚未确认转发目标。
- 绿色：SSH 隧道已连接。
- 红色：连接失败或掉线，原因保留到成功连接或手动停止。重试开始不会提前清除错误。

菜单显示错误类别，悬停可查看原因和建议。「概览」中的隧道卡片展示每个隧道的状态、排查建议、SSH 原始错误，并提供重试、连接开关与复制错误按钮。包括 SSH 配置异常、认证失败、连接被拒、主机不可达、DNS 故障、主机密钥变更、端口占用及掉线等分类；不能确定时保留原始 SSH 错误。

连接前会检查本地监听者：能核对主机别名和 `-L` 转发参数的 SSH 隧道统一显示「已连接」，避免重复启动。关闭开关或退出 App 会关闭该连接；发出关闭信号前会重新核对进程与转发参数。无法核对目标时显示橙色「连接待确认」，不会把未知进程当成已连接，也不会结束它。每 3 秒检查已有监听是否仍存在，退出后自动尝试建立连接。

如果是其他进程占用，或 SSH 实际报告绑定冲突，则显示无法创建新转发，每 3 秒重试一次，最多两次（首次连接不计入重试）。耗尽后停止自动重试；手动点击「重试」或重新开启可开始新一轮。已有监听可能本身就是正常工作的服务，不要求直接结束它。

真正连接失败或掉线后，连接开关自动关闭，红色原因继续保留。端口冲突待重试时开关也显示关闭，故障卡片显示重试进度，并可「取消重试」。其他类型故障直接停止，需要手动重试。「清除错误」会回到灰色停止状态。已有 SSH 连接的定时检查不属于失败重试，不消耗这两次额度。

设置中输入重复端口会即时提示并阻止保存。两个隧道都停止后才可保存，配置会在下次启动时保留，远端端口仍固定为 17890 / 17891。连接时也检查其他隧道是否已使用同一本地端口，第二个隧道等待而不竞争；外部进程占用则以 SSH 的实际绑定错误为准。

## SSH 配置

如果未配置 `aws-proxy` / `local-proxy` 别名，或 SSH 报告配置语法错误、密钥缺失、密钥格式或权限异常，应用显示「SSH 配置异常」，提示检查 `~/.ssh/config` 的 `Host`、`HostName`、`User`、`Port`、`IdentityFile`。请先在终端运行 `ssh aws-proxy` 或 `ssh local-proxy` 验证配置，修正后手动重试。原始错误会保留并支持复制；普通服务器域名解析失败仍显示为 DNS 问题。

复用系统 `/usr/bin/ssh`、`~/.ssh/config` 和 SSH agent，不存储密码、不修改配置。需要密码、私钥口令或 keyboard-interactive 验证码时，通过随应用打包的原生 SSH_ASKPASS 弹窗输入，答复仅经 SSH 的私有管道传递。首次连接会展示服务器指纹，需手动确认；主机密钥变更仍由 OpenSSH 拒绝。

取消弹窗会终止本次认证；停止隧道后，未完成的认证弹窗会自动关闭。密码错误或账号被服务器拒绝仍会报告认证失败；优先通过详情里的完整错误排查。

本应用通过私有 control socket 检查自己管理的会话，外部隧道则通过 SSH 监听进程及匹配的转发参数识别。两者都不代表远端代理服务的健康检查。仅关闭已核对为这两个目标的 SSH 会话，不会按端口结束未知进程。

产物使用本机临时签名，尚未进行 Developer ID 签名或公证。

## 验证

```sh
bash test.sh
```

使用模拟 SSH 测试并发会话、重复启动、认证及绑定错误、掉线、错误保留、重试取消、端口释放后的恢复、外部监听识别、关闭已匹配连接、保护未核对的进程，以及设置的冲突检查和持久化；不连接真实服务器。真实服务器及 GUI 交互需本机验收。
